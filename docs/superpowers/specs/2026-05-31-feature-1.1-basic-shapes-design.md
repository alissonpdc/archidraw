# Feature 1.1: Formas Básicas — Design Spec

**Date:** 2026-05-31  
**Feature:** 1.1 — Basic Shapes  
**Scope:** Canvas-based shape creation with 7 shape types, default styling, and JSON export  

---

## 1. Overview

Feature 1.1 allows users to create basic shapes on the archidraw canvas via toolbar buttons or keyboard shortcuts. Once created, shapes are visible with default styling (black outline, white fill) and can be exported as `.archidraw` JSON for persistence and re-editing.

**Success Criteria:**
- User can create all 7 shapes on the canvas
- Shapes render with consistent default styling
- Shift+drag maintains aspect ratio (perfect square/circle)
- All shapes export to valid `.archidraw` JSON
- All shapes can be re-imported without data loss

---

## 2. Shape Creation — Functionality & UX

### 2.1 Toolbar & Keyboard Shortcuts

**Toolbar** (top of screen):
- 7 buttons, one per shape type
- Active button is highlighted/pressed state
- Each button shows the shape icon and tooltip with keyboard shortcut

**Keyboard Shortcuts:**
- `R` — Rectangle
- `C` — Circle
- `D` — Diamond
- `T` — Triangle
- `L` — Line
- `A` — Arrow
- `X` — Text

### 2.2 Drawing Interaction

1. User selects tool (button or keyboard)
   - Cursor changes to indicate active tool
   - Button/highlight shows selected state
2. User clicks-and-drags on canvas
   - Shape appears and grows as they drag
   - Dimensions update in real-time (live feedback)
3. User releases mouse → shape is created and stays on canvas
4. **Shift+drag:** Maintains aspect ratio
   - Rectangle → perfect square
   - Circle → perfect circle (implicit, depends on shape type)
   - Other shapes: maintain proportions proportionally

### 2.3 Text Shape (Shape Type 7)

Text shapes are special:
- Created by pressing `X` or clicking Text button
- Click-drag creates a text box on the canvas
- Text box is **immediately active** (no double-click required)
- User types, text appears live as they type
- When user clicks elsewhere on canvas, text edit mode ends

## 3. Supported Shapes

| # | Shape | Type | Notes |
|---|-------|------|-------|
| 1 | Rectangle | Polygon | 4-sided, axis-aligned |
| 2 | Circle | Ellipse | Round, Shift+drag = perfect circle |
| 3 | Diamond | Polygon | 4-sided, rotated 45° |
| 4 | Triangle | Polygon | 3-sided, point up |
| 5 | Line | Path | 2 endpoints, no fill, stroke only |
| 6 | Arrow | Path | Line with arrowhead at end, stroke only |
| 7 | Text | Text | Text box, editable inline |

---

## 4. Visual Appearance & Styling

### 4.1 Default Styling

All shapes (except lines/arrows) use:
- **Stroke:** Black (#000000)
- **Stroke width:** 2px
- **Fill:** White (#FFFFFF)
- **Opacity:** 1.0

Lines and arrows use:
- **Stroke:** Black (#000000)
- **Stroke width:** 2px
- **No fill**

Text shapes:
- **Text color:** Black (#000000)
- **Font size:** 14px (default)
- **Font family:** System default (sans-serif)
- **No background fill** (just text)

### 4.2 Canvas

- **Background:** White (#FFFFFF)
- **No visible grid**
- **Infinite canvas** (users can draw anywhere; scroll if needed for later features)

### 4.3 Z-Order (Stacking)

- Shapes stack in **creation order**
- Last created shape appears on top
- Explicit reordering (bring to front/send back) comes in feature 3.2

## 5. Shape Data Model

Each shape stores:

```
Shape {
  id: string (UUID)
  type: "rectangle" | "circle" | "diamond" | "triangle" | "line" | "arrow" | "text"
  x: number (top-left or anchor point)
  y: number (top-left or anchor point)
  width: number (0 for lines/arrows)
  height: number (0 for lines/arrows)
  rotation: number (0 for now, comes in feature 2)
  text: string (empty for non-text shapes)
  createdAt: timestamp (for z-order)
  
  // Styling (default values, not editable yet)
  strokeColor: string ("#000000")
  strokeWidth: number (2)
  fillColor: string ("#FFFFFF" for shapes, null for lines/arrows)
}
```

---

## 6. Canvas Rendering

- **Rendering:** HTML5 Canvas 2D API
- **Render loop:** `requestAnimationFrame` (60 FPS target)
- **Shapes render in creation order** (z-order by timestamp)
- **Default styling applied by renderer** (not stored per-shape for simplicity)

---

## 7. Export/Import (`.archidraw` Format)

### 7.1 Export

When user exports:
- All shapes on current canvas are serialized to JSON
- Format: Array of shapes + metadata

```json
{
  "version": "1.0",
  "date": "2026-05-31T10:30:00Z",
  "shapes": [
    {
      "id": "shape-1",
      "type": "rectangle",
      "x": 100,
      "y": 100,
      "width": 200,
      "height": 150,
      "rotation": 0,
      "text": "",
      "strokeColor": "#000000",
      "strokeWidth": 2,
      "fillColor": "#FFFFFF",
      "createdAt": "2026-05-31T10:30:00Z"
    }
    // ... more shapes
  ]
}
```

### 7.2 Import

When user imports `.archidraw` JSON:
- File is loaded and parsed
- All shapes are added to canvas in order (preserving z-order)
- Canvas re-renders with imported shapes
- **100% fidelity** — no data loss

---

## 8. Constraints & Assumptions

- **Min shape size:** 1px × 1px (or 0px for lines)
- **Max canvas size:** 32-bit coordinates (per PRD)
- **Shape limit:** No hard limit; performance tested up to 1,000 shapes (per PRD)
- **Browser support:** Chrome, Firefox (latest 2 versions as of 2026-05-31)
- **No real-time collaboration** (single user per instance)
